# GEMINI.md

## Project Name

Diabetes Risk Prediction Web App

## Project Description

Build a modern fullstack web application for predicting diabetes risk using machine learning. The application allows users to input health-related data, receive a diabetes risk prediction, view confidence scores, understand the most influential factors, and save prediction history.

This project is intended as a portfolio project that combines web development, backend API design, database management, machine learning integration, and clean UI/UX design.

## Main Goal

Create a responsive, user-friendly, and production-ready web application that predicts diabetes risk based on user input using a trained machine learning model.

The system must clearly state that the prediction is only an estimation and not a replacement for professional medical diagnosis.

|---|---|

| Skin Thickness | Triceps skin fold thickness |

Each input must include:

## API Requirements

### Prediction Endpoint

Create an endpoint:

```http
POST /predict
```

Request body:

```json
{
  "pregnancies": 2,
  "glucose": 140,
  "blood_pressure": 80,
  "skin_thickness": 25,
  "insulin": 130,
  "bmi": 31.5,
  "diabetes_pedigree_function": 0.62,
  "age": 35
}
```

Response body:

```json
{
  "prediction": "High Risk",
  "confidence": 0.87,
  "main_factors": [
    "Glucose",
    "BMI",
    "Age"
  ],
  "message": "The model estimates a high diabetes risk. Please consult a healthcare professional."
}
```

## Database Tables

### users

Use Supabase Auth for user management.

### predictions

```sql
create table predictions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) on delete cascade,
  pregnancies int,
  glucose float,
  blood_pressure float,
  skin_thickness float,
  insulin float,
  bmi float,
  diabetes_pedigree_function float,
  age int,
  prediction text,
  confidence float,
  main_factors jsonb,
  created_at timestamp with time zone default now()
);
```

## Supabase Row Level Security Example

Enable RLS on the `predictions` table.

Suggested policies:

```sql
alter table predictions enable row level security;

create policy "Users can view their own predictions"
on predictions
for select
using (auth.uid() = user_id);

create policy "Users can insert their own predictions"
on predictions
for insert
with check (auth.uid() = user_id);

create policy "Users can delete their own predictions"
on predictions
for delete
using (auth.uid() = user_id);
```
